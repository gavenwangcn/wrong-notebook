# 错题列表性能优化报告

日期：2026-10-26。源码基线：`4d64e6c`。所有配对测试均按 A/B 顺序交替各运行 10 次，分位数使用 nearest-rank。

## 结论

一页 18 题原先查询并返回全部题目字段，包含 Base64 原图和 SVG 动画。真实响应的未压缩 JSON 为 1,212,462 字节，优化后相同卡片数据为 10,578 字节，减少 **99.13%**。改动通过数据库字段投影实现，不依赖缓存。

| 测量范围 | 优化前 p50 / p75 / p95 | 优化后 p50 / p75 / p95 | p75 降幅 |
| --- | --- | --- | ---: |
| 生产容器内，同一真实数据的查询与 JSON 序列化 | 148.96 / 155.68 / 251.01 ms | 16.37 / 21.17 / 89.96 ms | 86.40% |
| 两个隔离开发服务，合成数据，完整 HTTP 与 JSON 解析，不限速 | 23.31 / 28.60 / 36.66 ms | 15.58 / 16.83 / 93.62 ms | 41.15% |
| 同上，下载限制为 500,000 B/s（4 Mbps） | 2,307.42 / 2,402.04 / 2,405.87 ms | 24.05 / 29.21 / 53.98 ms | 98.78% |

生产数据对比仅进行只读查询，未部署新代码；它不包含认证和网络，不能作为线上完整接口的新耗时。完整 HTTP 对比使用本机的两个 Next.js 开发服务及相同的 52 题合成数据；前后响应分别为 1,209,056 和 10,688 字节，每对请求的卡片内容、顺序和分页一致。开发模式的小样本 p95 有调度或回收抖动，不能据此推断生产尾延迟。

限速场景只限制响应下载带宽，没有人为增加 20 ms RTT；它不是完整的 Fast 4G 浏览器模拟。curl 不请求内容压缩，字节数为未压缩 JSON。此服务没有 CrUX 数据。上述实验结果不能替代部署后的真实设备与网络验证。

## 行为与回归护栏

- 默认列表只读取题干、标签名、难度、日期、作答状态、掌握概率与计算复习状态所需的计数。
- 打印预览显式使用 `view=print`，保留原图、答案、解析、静态配图、卷别、年级学期和错题本名称。
- 题目详情接口继续负责完整题目内容；数据库字段、图片和持久数据均未修改。
- 真实 SQLite 测试为每题加入大图片和双语动画，18 题默认响应必须低于 12 KiB；同时检查分页、复习状态、用户隔离、打印和未登录访问。
- 784 项单元测试、409 项集成测试、lint 零警告和 TypeScript 检查均通过，未执行生产构建。

原有内部调用方已同步：列表使用 `ErrorItemSummary`，打印使用 `PrintableErrorItem`。外部脚本如曾依赖默认列表中的详情字段，应改用单题详情接口，打印数据使用 `view=print`。

## 重现配对测量

准备两个版本的服务，使用同一份非生产测试数据和同一认证信息。凭据放在权限为 `0600` 的临时文件中，文件仅包含 Cookie 请求头的值，不提交或输出。

```bash
PERF_COOKIE_FILE=/path/to/temporary-cookie \
node perf/bench/error-list.mjs \
  'http://127.0.0.1:3000/api/error-items/list?page=1&pageSize=18' \
  'http://127.0.0.1:3001/api/error-items/list?page=1&pageSize=18'

PERF_COOKIE_FILE=/path/to/temporary-cookie \
PERF_DOWNLOAD_BYTES_PER_SECOND=500000 \
node perf/bench/error-list.mjs \
  'http://127.0.0.1:3000/api/error-items/list?page=1&pageSize=18' \
  'http://127.0.0.1:3001/api/error-items/list?page=1&pageSize=18'
```

脚本先预热，再交替读取和解析完整响应；任何卡片或分页差异都会失败。时间结果用于测量收益，稳定的响应字节预算用于测试回归，避免把机器负载波动当作 CI 失败。
